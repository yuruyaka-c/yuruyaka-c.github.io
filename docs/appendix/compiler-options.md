# コンパイラ・オプション

## コンパイラ・オプションの利点

- C言語では、ソースコードをコンパイルするときに、追加の設定として**コンパイラ・オプション**を指定できる
- コンパイラ・オプションを使うと、**どの C 言語の規格でコンパイルするか**をはっきり指定できる
- コンパイラ・オプションを使うと、コードのチェックをより厳しくでき、問題がありそうな箇所を**警告**として教えてもらえる
- 警告を確認すると、初歩的なミスや、あとで不具合の原因になりそうな書き方に早く気づける
- そのため、プログラムを実行してから原因を探すよりも前に修正しやすくなり、**より高い品質のプログラムを効率よく作りやすくなる**


## コンパイラ・オプションの指定

### 最小限の指定

- 最小限の指定（オプションなし）でコンパイルする基本形は次のとおり

```txt title="基本的なコンパイル"
gcc hello.c -lm
```

!!!info "コマンドの意味"
	- `hello.c` をコンパイルし、実行可能ファイル `a.out` を生成する
	- GCC 15 以降では **C23**, それ以前のバージョンでは **C17** としてコードを解釈する
	- `-lm` は、数学関数ライブラリをリンクするための指定（**第 10 章** で登場）

### より詳細な指定

- C 言語の規格を明示したり、コードを詳しく検査したりしたい場合は、オプションを追加する

=== "GCC 14 以降"
	```txt title="オプションを増やしてコンパイル"
	gcc -Wall -Wextra -Wvla -Wstrict-prototypes -Wconversion -Wshadow -pedantic -std=c23 hello.c -lm
	```

=== "GCC 13"
	```txt title="オプションを増やしてコンパイル"
	gcc -Wall -Wextra -Wvla -Wstrict-prototypes -Wconversion -Wshadow -pedantic -std=c2x hello.c -lm
	```

!!!info "コマンドの意味"
	- `hello.c` をコンパイルし、実行可能ファイル `a.out` を生成する
	- 通常より多くの観点からコードを検査する
	- **C23** としてコードを解釈する


- 主なオプションの意味は次のとおり。オプションの順番は問わない

| オプション                 | 説明                                 |
| --------------------- | ---------------------------------- |
| `-Wall`               | よくある間違いを広く（All）警告する               |
| `-Wextra`             | `-Wall` では出ない追加（Extra）の警告も有効にする |
| `-Wvla`               | 可変長配列（VLA）を使ったときに警告する                   |
| `-Wstrict-prototypes` | 関数宣言が厳密（Strict）な形式に沿っているかを確認する  |
| `-Wconversion`        | 型変換により意図しない値の切り捨てや符号の変化が起こる可能性を警告する    |
| `-Wshadow`            | シャドーイングを警告する           |
| `-pedantic`           | 標準規格への厳密さを要求し、gcc 独自の拡張に対しても警告を出す   |
| `-std=c23`            | 使用する C 言語の規格を C23 に指定する（GCC 13 では `-std=c2x`） |

- コマンドが長く感じるかもしれないが、暗記する必要はない
- 一度入力すれば、ターミナルの**コマンド履歴**（++up++, ++down++）で再利用できる

### さらに厳しくするには

- さらに厳しくしたい場合は、`-Werror` を追加できる
- これは**警告をエラーとして扱う**オプションで、1 つでも警告が出るとコンパイルは失敗する
- 警告を放置しにくくなるため、コード品質を保ちやすくなるが、学習の初期段階では少し厳しいかもしれない

=== "GCC 14 以降"
	```txt title="-Werror を追加した例"
	gcc -Wall -Wextra -Werror -Wvla -Wstrict-prototypes -Wconversion -Wshadow -pedantic -std=c23 hello.c -lm
	```

=== "GCC 13"
	```txt title="-Werror を追加した例"
	gcc -Wall -Wextra -Werror -Wvla -Wstrict-prototypes -Wconversion -Wshadow -pedantic -std=c2x hello.c -lm
	```


## 警告の例

- 次のコード例で、警告がどのように役立つかを確認する

```c title="⚠️ 問題のあるコードの例"
#include <stdio.h>

int main()
{
	printf("%d %d %d\n", 100, 200.2);

	123;
}
```

- このコードには、少なくとも次の 3 つの問題がある
	- 3 つ目の `%d` に対応する引数が不足している
	- 2 つ目の `%d` に `double` 型の値 `200.2` を渡している
	- `123;` は実質的に何の効果もない
- 基本的なコンパイルコマンドだけでは、警告が表示されないコンパイラもある

```txt title="基本的なコンパイルコマンドでの警告例"
（なし）
```

---

- 一方で、警告を強化してコンパイルすると、次のような警告が表示される

```txt title="強化後のコンパイルコマンドでの警告"
hello.c: 関数 ‘main’ 内:
hello.c:5:21: 警告: 書式 ‘%d’ は引数の型が ‘int’ であると予期されますが、第 3 引数の型は ‘double’ です [-Wformat=]
    5 |         printf("%d %d %d\n", 100, 200.2);
      |                    ~^             ~~~~~
      |                     |             |
      |                     int           double
      |                    %f
hello.c:5:24: 警告: 書式 ‘%d’ は対応した ‘int’ 引数が予期されます [-Wformat=]
    5 |         printf("%d %d %d\n", 100, 200.2);
      |                       ~^
      |                        |
      |                        int
hello.c:7:5: 警告: 効果がない文です [-Wunused-value]
    7 |     123;
      |     ^~~
```

- ここでは、`printf` の書式指定子と実引数の対応が崩れていること、そして `123;` が無意味な文であることなど、先ほど挙げた問題点が警告として指摘されている
- このように、コンパイル時の警告は、実行してから気づくと厄介な問題を事前に見つける助けになる
- 警告を確認しながら修正する習慣を付けると、バグを減らしやすくなり、開発も進めやすくなる
